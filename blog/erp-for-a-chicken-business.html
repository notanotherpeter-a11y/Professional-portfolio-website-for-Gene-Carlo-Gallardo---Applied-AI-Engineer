How I Built a Full ERP for a Filipino Chicken Business in 3 Weeks

August 2026 · 5 min read · Gene Carlo Gallardo

Manok Manifesto is a home-based Filipino grilled chicken (inasal/inihaw) business based in the Philippines. When I took on the project, the owner was tracking orders on paper, managing inventory through memory and WhatsApp messages, and had no way to see how the business was actually performing at a glance.

Three weeks later, they had a full ERP system live at admin.manokmanifesto.com. Here's exactly how it happened.

The Problem With "Good Enough" Tools

The business didn't have a tech problem — it had a visibility problem. Orders came in through Facebook Messenger and WhatsApp. Inventory was restocked based on gut feel. Payroll was calculated manually at the end of each week. Expenses were tracked in a notebook.

This works at a small scale. It breaks the moment you try to grow. You can't make good buying decisions if you don't know your actual stock levels. You can't plan staffing if you don't know your busiest days. You can't raise prices confidently if you don't know your real cost base.

The goal wasn't to make the business more "tech-forward." The goal was to make it easier to make good decisions.

Choosing the Stack

For a home-based Philippines business, the stack had to be:

  • Fast to build — owner needed this running, not in planning for months
  • Cheap to run — no monthly server bills, no per-seat SaaS pricing
  • Reliable on mobile — most access would be via phone, not desktop
  • Real-time — inventory changes needed to reflect immediately

I went with: Vite + React + Tailwind + shadcn/ui for the frontend, Supabase for the database and auth, and Cloudflare Pages for hosting. Total ongoing cost: essentially zero for this scale.

What Was Built

The system shipped with 12 functional modules:

  • Dashboard — revenue KPIs, order counts, expense totals at a glance
  • Inventory (Weekly Checklist) — stock tracking by day with Start/Used/Delivered quantities, auto-carry logic, and low-stock highlighting
  • Orders — full order management with status flow
  • Expenses — categorised expense logging with monthly totals
  • Payroll — staff payroll periods and entries
  • Fund — cash fund tracking with inline-editable descriptions
  • Sales — revenue tracking separate from order management
  • Reports — monthly performance summaries
  • Users — admin-controlled user creation with role-based access
  • To Do List — operational task management
  • Settings — system configuration
  • POS — point-of-sale for in-person transactions

The Trickiest Part: Inventory Logic

The weekly checklist was the most technically interesting module. Each item tracks three values per day: S (Starting stock), W (Stock withdrawn/used), and D (Stock delivered/received).

The auto-carry logic works like this: next day's S = today's S − W + D. If the operator manually overrides an S value, auto-carry resumes from that manual value forward. Cross-week carry pulls from the last recorded day of the previous week. All auto-computed values are displayed in gray italics so the operator knows what's calculated vs. what they entered.

This meant only manually-entered Starting values are saved to the database. Auto values are recomputed on load via a computeEffectiveStocks() function — which keeps the data model clean and the DB queries simple.

Lessons From the Build

Ship the MVP, then fix the edge cases. The first version of the inventory system had invisible text in the modal inputs (dark theme CSS was overriding input colors). That got caught and fixed in day two. The business didn't need perfection on day one — they needed something to run on.

The contact form matters less than the login screen. I built a full immersive welcome/login screen with a Higgsfield-generated hero image of their signature lechon manok. The owner's face lit up when they first saw it. Software that feels like yours gets used more.

White-label ERP is a product, not a project. I now have a base ERP template that I can deploy for a new client in 1–2 days with module toggles, custom branding, and a fresh Supabase project. The next Philippine restaurant client costs me much less to build for — and I can price the value, not the hours.

The Result

Three weeks from the first conversation to a live system at a custom domain. The owner now has real-time visibility into inventory, a payroll system that doesn't require a calculator, and a dashboard that shows the business's financial health on first login.

That's what custom software is for.
